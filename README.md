# pattern_robot — робот паттерна 3+1 (перенос в новый чат)

Робот ищет паттерн «3+1» (три трендовые свечи + разворотная) на 5-минутках FORTS,
рисует стрелки/уровни на графике QUIK через `addLabel2`, считает аналитику
(ожидание, винрейт, рубли по 1 контракту, просадку, ГО, период) и **симулирует**
сделки. Реальные заявки выключены (`live_trading: false`).

## ВАЖНО: слоты QuikSharp (один слот — один клиент)

| Процесс | Слот (requests/callbacks) |
|---|---|
| Сборщик данных (collector) | 34130 / 34131 |
| **Этот робот** | **34140 / 34141** |
| (был старый слот робота) | 34142 / 34143 — свободен, под второй экземпляр |

Этот конфиг уже стоит на `34140/34141`, поэтому робот можно запускать параллельно
со сборщиком, не конфликтуя за единственного клиента моста.

## Сейчас: один инструмент (Уровень 1)

В `config.json` оставлен **один инструмент — Si** (живой по логам; RTS стабильно лил).
Код не менялся — он по-прежнему умеет список, ему просто дали один элемент.

**Переключить на RTS** — заменить блок `instruments` на:
```json
"instruments": [
    { "name": "RTS", "prefix": "RI", "ticker": null, "chart_tag": "rts5m", "price_step": 10 }
],
```

**Торговать оба сразу** = два запущенных экземпляра, каждый со СВОИМ слотом и конфигом
(Si → 34140/34141, RTS → 34142/34143). Это и есть изоляция по инструментам.

## План на новый чат

- **Уровень 2 (настоящая чистка):** конфиг `instrument: {...}` вместо списка,
  аналитика — одна карточка без «Вместе», лог без префиксов `[Si]/[RTS]`. Код станет
  проще и честнее.
- **Уровень 3 (на потом):** выпадающий выбор инструмента прямо в окне (несколько
  профилей в конфиге, переключатель + Стоп/Старт).

## Запуск

```
run_window.bat   # окно робота (GUI): Старт размечает историю и идёт онлайн
run_scan.bat     # разовый скан истории в консоль (без онлайна)
python pattern_robot.py --mock   # проверка логики без QUIK
```

Перед запуском держи в QUIK открытым график нужного ТФ с тегом из конфига
(`si5m` / `rts5m`) — на него робот рисует. `slot.quik_py_dir` укажи на папку QuikPy,
если не находится сам.

## Файлы

## Календарный фильтр входов

Робот проверяет каждый найденный сигнал 3+1 через `event_calendar.is_entry_blocked`
(см. `EVENT_CALENDAR.md`): в день ЦБ (13:00-15:30), в среду в окно недельной CPI
(18:45-19:30) и в клиринг (14:00-14:05, 18:50-19:05) вход НЕ выставляется — стрелка
на графике всё равно рисуется, но рядом добавляется метка `ФИЛЬТР: <причина>`
(оранжевым, на противоположной стороне от стрелки) и в лог/окно попадает пометка
«ЗАБЛОКИРОВАНО КАЛЕНДАРЁМ». Управляется блоком `calendar_filter` в `config.json`:

```json
"calendar_filter": { "enabled": true, "hard_only": false }
```

`hard_only: true` оставляет только жёсткий блок (день ЦБ), `enabled: false`
выключает фильтр полностью (сигналы отрабатывают как раньше).

Подключение — НАПРЯМУЮ через QuikPy (`slot.quik_py_dir`), `quik_link.py` роботу не нужен
(он у read-only модулей: проверка связи, сборщик).

## Текущее состояние аналитики (что уже умеет)

- ожидание на сигнал / на сделку (в R), винрейт, сумма R, безубыток по rr;
- рубли по 1 контракту (стоимость пункта из QUIK: STEPPRICE/шаг);
- макс. просадка (R и ₽) + серия стопов подряд;
- ГО (нач. маржа BUYDEPO/SELLDEPO) + «ГО на набор»;
- период (охват графика, дни) + частота сделок/нед.;
- разбивка по размеру риска (мелкий/крупный по медиане).

## Известные мелочи (на потом, не баги)

- В `chart.py` цвет png-стрелок (bull=красный/bear=зелёный по конфигу) противоположен
  цвету текстового фолбэка (BUY=зелёный/SELL=красный). Пока png нет — работает фолбэк.
- При одном инструменте строка «Вместе» в аналитике дублирует единственную карточку —
  уйдёт на Уровне 2.

## Главное про данные (контекст)

Выборка пока крошечная (~месяц 5-минуток, ~10 сделок) — на ней эдж от шума не отличить,
и любой подбор фильтров/параметров = оверфит. Глубину набирает отдельный **сборщик**
(collector, слот 34130/34131) — копит 5-минутки вперёд. Робот — «лаборатория»: тут
эксперименты и аналитика; данные копятся независимо.
